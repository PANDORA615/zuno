# Архитектура и протокол

```text
Browser (React/MUI, HTML5 / YouTube IFrame API)
  | HTTPS / Socket.IO                 | direct video
Caddy                                YouTube / HTTPS MP4 origin
  | static: dist/web
  | /api, /socket.io -> 127.0.0.1:3000
Fastify + Socket.IO (one Node 24 process)
  | SQLite WAL: users, rooms, members, messages, videos, history
  | /var/lib/zuno/videos (private MP4)
```

## Структура

- `server/app.ts`: HTTP API, подпись сессии, Socket.IO, авторизация, валидация, файловые лимиты/Range.
- `server/db.ts`: создание persistent каталогов, миграция 1 и WAL.
- `web/src/main.tsx`: страницы, управление комнатой, чат, история, профиль.
- `web/src/player.tsx`: HTML5 и официальный YouTube API, коррекция времени, подавление эха.
- `deploy/`: Caddy, systemd, backup timer, лимит журналов, установка Node с SHA-256.
- `scripts/`: сборка релиза и безопасный SQLite online backup.
- `tests/`: HTTP/WebSocket integration и настоящий browser E2E.

## Сессии и доступ

Cookie `zuno` содержит подписанный случайный 192-битный ID, HttpOnly, SameSite=Strict, Secure в production, TTL cookie — год. HMAC проверяет @fastify/cookie; входящий userId никогда не принимается от клиента. Секрет минимум 32 символа. Один браузер = одна гостевая личность; разные устройства имеют разные сессии.

Room ID и invite token — независимые 192-битные случайные значения. БД хранит SHA-256 invite token, ссылка передаёт его в fragment; клиент удаляет fragment после обмена на членство. Место резервируется постоянным членством: максимум 5 человек, включая ведущего, независимо от числа вкладок/socket-соединений. Просмотр другим устройством того же человека занимает отдельное место. Ведущий может ротировать ссылку или отозвать всех зрителей. Права проверяются заново для каждого события и каждого Range.

POST/PATCH/DELETE требуют точного `Origin`, WebSocket handshake требует того же Origin (для same-origin polling допускается браузерный `Sec-Fetch-Site: same-origin`). Socket.IO не включает wildcard CORS. Сервис слушает loopback за Caddy. CSP запрещает произвольные iframe/object и сторонние скрипты, разрешая только YouTube API. React рендерит сообщения текстом. Referrer-Policy strict-origin-when-cross-origin сохраняет Origin-идентификацию, необходимую YouTube embed, и не передаёт путь комнаты внешним сайтам.

## HTTP API

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/health` | SQLite healthcheck, без создания гостя |
| GET / PATCH | `/api/me` | Сессия, лимиты / ник |
| GET / POST | `/api/rooms` | Мои комнаты / создать |
| POST | `/api/join` | `{token}` → постоянное членство |
| POST | `/api/rooms/:id/invite` | Ротация токена, только ведущий |
| POST | `/api/rooms/:id/control` | `{enabled}` управление всеми |
| POST | `/api/rooms/:id/revoke` | Исключить приглашённых и отозвать токен |
| GET | `/api/history` | Только личная история |
| GET / POST | `/api/videos` | Мои файлы / multipart MP4 |
| GET / HEAD / DELETE | `/api/videos/:id` | Авторизованный stream/Range / удаление владельцем |

Лимиты: HTTP 120 запросов/мин/IP, upload 5/мин/IP, Socket.IO 100 событий/10 с/соединение, чат не чаще одного сообщения в 700 мс на пользователя. Chat ≤1000 символов, ник ≤32, пакет WebSocket ≤16 КБ. Ведущий может создать максимум 20 комнат. Комнаты без активности удаляются через 30 дней (настраивается). Удаление комнаты каскадно удаляет её чат/историю/членство; пользовательские файлы удаляются владельцем отдельно.

## События Socket.IO

- `join(roomId, ack)`: проверка членства; ответ `snapshot` с состоянием, членами, online и последними 100 сообщениями. Reconnect вызывает join снова.
- `command({roomId,revision,action,positionSeconds,sourceType?,sourceId?}, ack)`: `source`, `play`, `pause`, `seek`. Только ведущий/разрешённые участники. Ревизия должна точно совпадать; иначе возвращается актуальный snapshot, команда отклоняется. Повторите сознательно — автоматический retry старой команды не выполняется.
- `state({state,serverNow})`: подтверждённое состояние комнаты. `state = {sourceType,sourceId,positionSeconds,isPlaying,updatedAt,revision,actorId}`. roomId — ID канала/envelope комнаты. Каждая успешная команда увеличивает revision, последнее действие разрешается сервером последовательно.
- `sync(roomId)`: прочитать актуальное состояние без новой команды/revision.
- `chat({roomId,text}, ack)`, `message({id,userId,nickname,text,createdAt})`.
- `progress({roomId,duration})`: позицию берёт сервер из состояния, duration валидирует; клиент не может записать чужую историю или произвольную позицию прогресса.

Во время воспроизведения позиция = `positionSeconds + max(0,serverNow-updatedAt)/1000`. На клиенте оценка serverNow обновляется по timestamp полученных событий; это не измерение RTT. Каждые 3 с отклонение >1.3 с корректируется seek. API-события после серверного применения кратко подавляются для исключения эха. При буферизации отображается локальный статус; абсолютная синхронность не обещается. Для большой сетевой задержки потребуется измерение RTT и более тонкая коррекция playbackRate.

## Видео и хранение

Прямые URL сервер **не скачивает**, поэтому серверного SSRF-fetch маршрута нет. Клиент получает HTTPS URL и открывает его непосредственно. Не используйте секретные внутренние URL как общедоступные источники. YouTube ID проверяется; запрещённые к embed ролики не обходятся. iframe произвольного сайта не вставляется.

Upload: один MP4, MIME `video/mp4`, сигнатура `ftyp`, до 50 МБ, общая квота 200 МБ, резерв диска 100 МБ. Параллельные upload сериализованы, подсчёт и запись потоковые. Диск/квота проверяются до и во время записи; при неуспехе частичный файл удаляется. Имя на диске — случайный ID, исходное имя — только подпись. Участник получает файл, только если он владелец или файл сейчас выбран в доступной ему комнате. Уже открытое потоковое соединение может завершиться после отзыва членства; новые GET/Range будут отклонены.

Чат и просмотр сохраняются в SQLite, а не памяти процесса. История обновляется для подключённых участников; известная длительность даёт процент. Онлайн-статус transient, после рестарта восстанавливается по socket-подключениям.

Полноценные API-адаптеры RUTUBE/VK и HLS не включены: отключённые карточки явно сообщают это. Ни логотип, ни iframe сами по себе не считаются интеграцией.
